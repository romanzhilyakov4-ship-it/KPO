# ПОС — ДЗ №2 по КПО

Консольная программа для оценивания студентов по критериям. Можно добавлять, изменять и удалять студентов и критерии, выставлять и исправлять оценки, смотреть итог и экспортировать ведомость. Данные сохраняются в `data.json` между запусками.

## Запуск

Нужен Python 3.10 или новее. Из папки `hw2`:

```bash
python main.py
```

Простой пример: `1` — добавить студента, `5` — критерий (например, «Домашние задания», максимум `10`, вес `2`), `9` — поставить балл, `12` — посмотреть итог, `14` — выгрузить `итоги.csv`. Для чисел подходят точка и запятая. Дополнительные библиотеки не нужны.

Тесты запускаются командой:

```bash
python -m unittest discover -s tests -v
```

## Доменная модель (DDD)

Общий язык программы: **студент, критерий, рубрикатор, оценка, балл, вес, итог**.

- `Student` и `Criterion` — **Entity**: имеют ID, который не меняется при переименовании.
- `Score` — **Value Object**: неизменяемый балл без своего ID.
- `Course` — корень агрегата: хранит студентов, рубрикатор и оценки, проверяет их связи.
- `Evaluation` — выставленный балл конкретному студенту по конкретному критерию.
- `ResultCalculator` — **Domain Service** для расчёта итога по текущим оценкам.
- `CourseRepository` — порт (**Repository**), через который приложение сохраняет курс.

**Правила:** балл от 0 до максимума критерия; оценить можно только существующего студента и существующий критерий. Максимум и вес положительны, названия непустые. При удалении студента или критерия его оценки удаляются. При уменьшении максимума уже выставленные оценки не должны стать недопустимыми. При чтении сохранённых данных правила проверяются заново.

Итог в процентах: `100 × сумма(балл / максимум × вес) / сумма весов`. Если оценка не выставлена, для полного итога это 0. Дополнительно показывается промежуточный результат только по выставленным оценкам. Пустой рубрикатор даёт 0%.

## Архитектура и паттерны

Выбрана **Ports & Adapters**:

- `pos/domain.py` — доменная модель и расчёт, не зависит от файлов и консоли;
- `pos/application.py` — сценарии работы и интерфейсы хранения/экспорта;
- `pos/adapters.py` — сохранение JSON и экспорт CSV;
- `main.py` — консоль и `Container`, собирающий зависимости (**DI**);
- `tests/test_pos.py` — проверки предметных правил и сценариев.

Зависимости: `main → application → domain`, `adapters → application и domain`. Внутренние слои не импортируют внешние.

Применены три паттерна GoF:

1. **Factory (порождающий)** — `EvaluationFactory.create` создаёт оценку и сразу проверяет допустимый балл.
2. **Facade (структурный)** — `PosFacade` даёт консоли одну точку доступа к сценариям, скрывая работу с хранилищем и экспортом.
3. **Strategy (поведенческий)** — `FullRubric` и `GradedOnly` меняют правило учёта отсутствующих оценок в `ResultCalculator`.

Никаких внешних зависимостей и дополнительных настроек нет. JSON хранится рядом с `main.py`, CSV по умолчанию создаётся в рабочей папке и открывается в табличных редакторах.
